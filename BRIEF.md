# NEXT PATH

Полное описание проекта, функционала, логики, дизайна и структуры продукта.

---

## 1. Общая идея проекта

Next Path — цифровая профориентационная веб-платформа для школьников 8–11 классов и абитуриентов, которая помогает пройти путь от понимания собственных интересов и склонностей до конкретного выбора профессии, университета и дальнейшего карьерного маршрута.

Главная идея проекта — не просто показать пользователю результаты теста, а провести его по всей цепочке принятия решения:

> Я → мои интересы → подходящие направления → профессии → университеты → поступление → карьерный путь.

Сейчас информация для выбора профессии и университета разбросана по множеству разных сайтов. Пользователю приходится отдельно проходить тесты, искать описание профессий, сравнивать университеты, искать стоимость обучения, требования для поступления, гранты и сроки.

Next Path объединяет этот путь в одной системе.

---

## 2. Целевая аудитория

Основная аудитория:

- школьники 8–11 классов;
- старшеклассники, которые не определились с профессией;
- абитуриенты;
- школьники, которые выбирают профильные предметы;
- пользователи, которые уже примерно знают направление, но не знают, какую профессию выбрать;
- пользователи, которые знают профессию, но не знают, где на неё учиться.

Основной возраст — примерно 14–18 лет.

Платформа должна быть максимально понятной человеку без специальных знаний о профориентации, университетах или рынке труда.

---

## 3. Основная проблема

Школьник часто сталкивается сразу с несколькими проблемами:

1. Не понимает, какая профессия ему подходит.
2. Не знает свои сильные стороны.
3. Не знает, какое направление выбрать.
4. Не понимает разницу между похожими профессиями.
5. Не знает, какие школьные предметы нужны.
6. Не знает, какие навыки требуются.
7. Не понимает уровень зарплаты и востребованность профессии.
8. Не знает, в каких университетах можно получить нужное образование.
9. Не умеет сравнивать университеты.
10. Не знает стоимость обучения.
11. Не знает о грантах.
12. Не знает сроки и этапы поступления.
13. Не понимает, как будет выглядеть карьерный путь после обучения.

Next Path должен решить эту проблему в одном продукте.

---

## 4. Основной user flow

Основной сценарий пользователя:

> Главная → тестирование → результаты → направление → профессии → конкретная профессия → университеты → конкретный университет → план поступления → карьерный путь.

При этом пользователь не обязан проходить всё именно последовательно. Он может:

- сразу открыть направления;
- найти профессию;
- найти университет;
- добавить информацию в избранное;
- вернуться к результатам теста;
- изучить карьерную карту;
- открыть план поступления.

То есть платформа должна поддерживать как guided journey, так и свободное исследование.

## 5. Главная страница

Главная страница должна сразу объяснять: что такое Next Path, для кого он, что пользователь получит.

Главный CTA: **«Пройти тест»**

Дополнительные CTA:

- «Исследовать профессии»
- «Посмотреть направления»
- «Найти университет»

### Структура главной страницы

**Первый экран** содержит:

- логотип Next Path;
- навигацию;
- переключатель языка;
- основной заголовок;
- короткое объяснение продукта;
- основную кнопку «Пройти тест»;
- визуальный элемент, связанный с карьерным выбором.

Пример смыслового посыла: «Найди свой следующий шаг» или аналогичная формулировка.

Важно, чтобы пользователь сразу понял: Next Path не выбирает профессию за человека — он помогает ему сделать осознанный выбор.

**Блок «Как это работает»** — 4 основных шага:

1. **Узнай себя.** Пройди профориентационное тестирование.
2. **Изучи направления.** Посмотри сферы, которые соответствуют твоим результатам.
3. **Найди профессию.** Сравни профессии, зарплату, востребованность, навыки и требования.
4. **Построй свой путь.** Выбери университет и получи план дальнейших действий.

**Блок направлений.** Показываются основные направления. На сегодняшний день предусмотрены:

1. IT / AI
2. Медицина
3. Инженерия / Архитектура
4. Бизнес / Экономика
5. Дизайн / Творческие профессии
6. Психология / Социальные науки
7. Право / Государственное управление
8. Образование / Наука
9. Сельское хозяйство / Agro

Каждое направление имеет отдельную карточку.

**Блок профессий.** Можно показать несколько популярных профессий с возможностью перейти в каталог. Карточка профессии должна содержать минимум:

- название;
- направление;
- краткое описание;
- ориентировочную зарплату;
- уровень востребованности;
- кнопку «Подробнее»;
- возможность добавить в избранное.

**Блок университетов.** Показываются примеры университетов. Пользователь может перейти в полный каталог.

**Финальный CTA.** Например: «Не знаешь, с чего начать? Пройди тест и получи свой маршрут.» Кнопка: «Начать тест».

## 7. Профориентационный тест

Это одна из главных функций Next Path. Тест должен быть коротким, понятным и не выглядеть как школьный экзамен. Главная задача — определить наиболее подходящие пользователю профессиональные направления.

Тест состоит из нескольких блоков. Проверяются:

**1. Интересы** — что пользователю нравится делать. Например: работать с технологиями; помогать людям; создавать что-то новое; анализировать информацию; работать с числами; общаться; проектировать; исследовать; организовывать; писать; работать руками.

**2. Склонности** — что человеку легче даётся. Например: аналитическое мышление; коммуникация; творчество; логика; работа с информацией; пространственное мышление; организация; исследование.

**3. Предпочтительный тип деятельности.** Например: работа с людьми; работа с данными; работа с технологиями; творческая деятельность; исследовательская работа; управление; практическая работа.

---

## 8. Логика теста

Каждый ответ пользователя связан с определёнными профессиональными направлениями. Ответы начисляют баллы направлениям.

После завершения теста система:

1. собирает ответы;
2. рассчитывает результаты;
3. определяет наиболее подходящие направления;
4. сортирует направления;
5. показывает процент соответствия.

Например:

- IT / AI — 87%
- Дизайн / Творчество — 76%
- Инженерия / Архитектура — 71%

Проценты должны рассчитываться автоматически.

---

## 9. Интерфейс теста

На странице теста:

- название теста;
- краткое объяснение;
- индикатор прогресса;
- текущий номер вопроса;
- вопрос;
- варианты ответа;
- кнопка перехода дальше;
- возможность вернуться назад;
- возможность завершить/выйти.

Например:

```
Вопрос 7 из 20
[текст вопроса]
○ Вариант 1
○ Вариант 2
○ Вариант 3
○ Вариант 4
[Далее]
```

## 10. Результаты теста

Это отдельная полноценная страница. После прохождения пользователь не должен получать просто «Вы подходите для IT». Результат должен быть информативным.

**Верхняя часть.** Заголовок «Твой результат» и краткое персонализированное объяснение. Например: «По результатам теста тебе особенно подходят направления, связанные с аналитикой, технологиями и проектированием.»

**Рейтинг направлений.** Показываются направления по степени соответствия:

- 1 место — IT / AI — 87%
- 2 место — Инженерия / Архитектура — 78%
- 3 место — Дизайн / Творчество — 69%

**Для каждого направления** показывается:

- процент совпадения;
- краткое описание;
- почему направление может подойти;
- какие профессии есть внутри;
- какие навыки важны;
- кнопка «Изучить направление».

---

## 11. Важная логика результатов

Результат нельзя позиционировать как окончательный вердикт.

Нужно показать, что тест «помогает определить направления, которые могут вам подойти», а не «определяет вашу единственную профессию».

Пользователь должен иметь возможность самостоятельно изучать другие направления.

---

## 12. Страница «Направления»

Каталог всех профессиональных направлений. Каждое направление — отдельная карточка:

- название;
- описание;
- ключевые навыки;
- примеры профессий;
- кнопка «Подробнее».

---

## 13. Страница конкретного направления

Например: Инженерия / Архитектура. Страница должна содержать:

**О направлении** — что это за сфера.

**Кому подходит** — какие качества и интересы полезны.

**Основные навыки** — математика; пространственное мышление; техническое мышление; проектирование; работа с программами; внимание к деталям.

**Школьные предметы** — например: математика; физика; информатика; черчение / графика.

**Профессии** — показывается список профессий.

---

## 14. Каталог профессий

Отдельная страница. Пользователь может:

- искать профессию;
- фильтровать;
- сортировать;
- открывать подробную информацию;
- добавлять профессию в избранное.

**Поиск.** Поле «Найти профессию». Поиск должен работать по названию.

**Фильтры** — по направлению; уровню востребованности; зарплате; сфере деятельности.

**Сортировка** — по названию; по зарплате; по востребованности; по соответствию результатам пользователя.

---

## 15. Карточка профессии

Каждая профессия имеет отдельную страницу. Обязательные блоки:

**Название профессии.**

**Краткое описание** — что делает специалист.

**Чем занимается** — основные рабочие задачи.

**Зарплата.** Важно показывать числовые значения, а не только слова «высокая/средняя/низкая». Например: «Средняя зарплата: X ₸». При наличии данных можно показывать диапазон: от X до Y ₸.

**Востребованность** — например «Высокая», с визуальным индикатором.

**Плюсы** — список преимуществ.

**Минусы** — список возможных сложностей.

**Необходимые навыки** — например: аналитическое мышление; коммуникация; программирование; работа с данными.

**Школьные предметы** — какие предметы желательно изучать.

**Подходящие направления** — связанные направления Next Path.

**Университеты** — список университетов, где можно получить соответствующее образование.

**Карьерный рост** — возможный путь: Junior → Middle → Senior → Lead / Manager / Expert, в зависимости от профессии.

**Кнопка** — «Посмотреть университеты».

Карточка университета, минимальная информация:

- название;
- страна;
- город;
- рейтинг;
- стоимость обучения;
- направления;
- доступные программы;
- контактная информация;
- официальный сайт;
- возможность добавить в избранное.

---

## 17. Фильтры университетов

Фильтры: страна; город; направление; стоимость; рейтинг; тип образования.

Поиск: «Найти университет».

---

## 18. Страница конкретного университета

Содержит:

**Основная информация** — название; страна; город; краткое описание.

**Рейтинг** — если есть соответствующие данные.

**Стоимость** — стоимость обучения за год.

**Направления** — какие направления представлены.

**Программы** — какие специальности доступны.

**Поступление** — основные требования.

**Контакты** — сайт; email; телефон, если есть; адрес.

**Связанные профессии** — какие профессии можно получить после обучения.

---

## 19. Связка «профессия → университет»

Это одна из важных функций платформы.

Если пользователь открыл профессию «Архитектор», он должен увидеть: где можно этому научиться? — и получить список подходящих университетов.

То есть профессии и университеты должны быть связаны в базе данных.

---

## 20. Связка «направление → профессия → университет»

Логика базы должна строиться примерно так:

```
Направление
    ↓
Профессии
    ↓
Образовательные программы
    ↓
Университеты
```

Это позволяет пользователю двигаться по логической цепочке.

---

## 21. Карьерная карта

Отдельная функция Next Path. Пользователь должен понимать не только «Кем я могу работать?», но и «Как мне туда прийти?».

Карьерная карта показывает путь: школа → образование → первая работа → развитие → карьерный рост.

Например, профессия UX/UI Designer:

1. Школьные предметы и навыки.
2. Выбор направления.
3. Университет / образовательная программа.
4. Портфолио.
5. Стажировка.
6. Junior Designer.
7. Middle Designer.
8. Senior / Lead.

---

## 22. План поступления

Отдельный раздел. Пользователь получает пошаговый checklist. Например:

1. Определить профессию
2. Выбрать университет
3. Проверить требования
4. Определить необходимые предметы
5. Проверить сроки
6. Подготовить документы
7. Подать заявку
8. Проверить возможность получения гранта
9. Подать документы
10. Отследить результат

---

## 23. Дедлайны

В плане поступления должны отображаться важные даты: регистрация; подача документов; экзамен; результаты; зачисление.

**Если конкретных данных нет, блок не должен показывать выдуманные даты.**

---

## 24. Гранты

В платформе предусмотрена информация о государственных образовательных грантах и других возможностях финансирования.

Пользователь должен понимать:

- что такое грант;
- кто может претендовать;
- какие требования;
- какие сроки;
- куда подавать документы;
- какие направления доступны.

---

## 25. Избранное

Пользователь должен иметь возможность сохранять:

- профессии;
- университеты;
- направления;
- возможно, образовательные программы.

После нажатия «♡ Добавить в избранное» объект появляется в разделе «Избранное».

---

## 26. Страница «Избранное»

Раздел может иметь категории: Все / Профессии / Университеты / Направления.

Пользователь может удалить объект из избранного.

Если ничего не сохранено: «Здесь пока ничего нет» и CTA «Исследовать профессии».

---

## 27. Поиск

На платформе необходим глобальный поиск. Пользователь вводит «Архитектор» и получает: профессии; направления; университеты; программы.

Поиск должен быть максимально понятным.

---

## 28. Отзывы студентов

Предусмотрен раздел с отзывами студентов. Отзыв может содержать: имя; университет; специальность; год обучения; текст; оценку, если используется.

Отзывы должны быть связаны с конкретным университетом/программой.

**Важно: если база отзывов не подключена, интерфейс не должен создавать фиктивные отзывы.**

---

## 29. Многоязычность

Платформа должна работать на трёх языках: русский, казахский, English.

Переключатель языка находится в интерфейсе. При смене языка должны корректно переключаться: интерфейс; кнопки; заголовки; описания; элементы навигации.

**Нельзя оставлять часть интерфейса на одном языке, а часть на другом.**

---

## 30. AI

AI-компонент, который обсуждался на ранних этапах проекта, не является обязательной частью текущей версии продукта. Основной продукт должен полноценно работать без AI.

Логика рекомендаций должна работать на основе:

- ответов теста;
- базы направлений;
- базы профессий;
- связей между направлениями и профессиями;
- данных об университетах.

Это делает MVP стабильнее и понятнее.

---

## 31. Авторизация

В текущей версии регистрация не должна быть обязательным барьером перед использованием продукта.

Пользователь должен иметь возможность: открыть сайт → пройти тест → получить результат → изучать информацию.

Если персональные функции требуют сохранения данных, они могут работать через пользовательскую сессию/профиль, но регистрация не должна мешать основному сценарию.

Главное — не заставлять школьника регистрироваться до того, как он увидит ценность продукта.

---

## 32. Дизайн

Дизайн должен выглядеть как реальный современный образовательный digital-продукт, а не как шаблон конструктора или AI-generated landing page.

Главные требования:

- современно;
- чисто;
- понятно;
- легко воспринимается подростками;
- не перегружено;
- визуально интересно;
- аккуратная типографика;
- хорошая иерархия;
- много воздуха;
- понятные CTA.

---

## 33. Цвета

Основной визуальный стиль — светлый. Не использовать большое количество тёмных или тяжёлых оттенков.

Предпочтительно:

- светлый фон;
- мягкие пастельные оттенки;
- аккуратные цветовые акценты;
- умеренное использование ярких цветов.

Цвет должен помогать ориентироваться в интерфейсе, а не просто украшать его.

---

## 34. Карточки

Карточки должны использоваться для: направлений; профессий; университетов; результатов теста; избранного.

Карточки:

- имеют чёткую структуру;
- не должны быть слишком перегружены;
- имеют понятную кнопку;
- визуально разделяются;
- должны хорошо выглядеть как на компьютере, так и на телефоне.

---

## 35. Типографика

Шрифт должен быть современным, хорошо читаемым, поддерживать русский, казахский и английский языки, иметь несколько начертаний.

Важно правильно разделять: H1; H2; H3; основной текст; подписи; кнопки; дополнительные данные.

---

## 36. Иконки и иллюстрации

Иконки должны быть единообразными. Не использовать множество разных стилей иконок.

Иллюстрации должны помогать пониманию информации. Не нужно перегружать сайт декоративной графикой.

Главное — содержание и удобство.

---

## 37. Кнопки

Все кнопки должны иметь понятные названия: Пройти тест; Начать; Далее; Назад; Завершить тест; Подробнее; Изучить направление; Найти университеты; Добавить в избранное; Удалить из избранного; Построить путь; Посмотреть профессию; Посмотреть университет; Найти; Сравнить.

Не использовать непонятные CTA типа «Узнать больше» там, где можно конкретно написать действие.

---

## 38. Состояния интерфейса

Каждая интерактивная функция должна иметь состояния:

- **Default** — обычное состояние.
- **Hover** — при наведении.
- **Active** — при нажатии.
- **Disabled** — недоступное состояние.
- **Loading** — загрузка данных.
- **Error** — ошибка.
- **Empty** — нет данных.

Например, если поиск ничего не нашёл: «Ничего не найдено» и предложение изменить запрос.

---

## 39. Адаптивность

Сайт должен нормально работать на компьютере, ноутбуке, планшете и телефоне. Особенно важно мобильное отображение, поскольку основная аудитория — школьники.

На мобильном:

- карточки перестраиваются;
- фильтры превращаются в удобную панель;
- меню становится компактным;
- текст не выходит за пределы;
- кнопки остаются удобными для нажатия;
- таблицы не ломают страницу.

---

## 40. База данных

Основные сущности:

**Directions** (направления): `id`, `name_ru`, `name_kz`, `name_en`, `description`, `skills`, `subjects`, `image/icon`.

**Professions** (профессии): `id`, `name`, `description`, `salary_min`, `salary_max`, `salary_average`, `demand`, `pros`, `cons`, `skills`, `subjects`, `direction_id`.

**Universities**: `id`, `name`, `country`, `city`, `rating`, `tuition_cost`, `website`, `email`, `phone`, `address`, `description`.

**Programs**: `id`, `university_id`, `direction_id`, `profession_id`, `program_name`, `requirements`, `tuition_cost`.

**Questions**: `id`, `question`, `options`, `category`.

**Answers** — ответ пользователя, связывается с вопросом и выбранным вариантом.

**Test Results** — хранится результат: пользователь; направление; процент; дата прохождения.

**Favorites** — связь user → object, где object может быть profession, university или direction.

**Reviews**: `id`, `university_id`, `author`, `program`, `year`, `text`, `rating`.

---

## 41. Важные связи в базе

- Direction 1 → Many Professions. Одно направление может иметь много профессий.
- Profession Many → Many Universities. Одна профессия может изучаться в разных университетах.
- University 1 → Many Programs. Университет имеет несколько программ.
- User → Test Results. Пользователь имеет результаты тестирования.
- User → Favorites. Пользователь сохраняет объекты.

---

## 42. Данные для таблиц

Данные могут первоначально подготавливаться в Google Sheets. Но на самом сайте информация должна отображаться через нормальную связанную базу данных.

Нельзя делать так, чтобы каждый экран был отдельной статичной страницей.

Например: если поменяли зарплату профессии в базе, она должна автоматически измениться во всех местах, где эта профессия отображается.

---

## 43. Фильтры должны быть реальными

- Если пользователь выбирает **IT / AI** — должны отображаться только связанные профессии.
- Если выбирает **зарплата от X** — результаты действительно должны фильтроваться по числовому значению.
- Если выбирает **Казахстан** — должны отображаться университеты Казахстана.

Фильтры не должны быть декоративными.

---

## 44. Сортировка

Сортировка также должна реально работать: зарплата по возрастанию; зарплата по убыванию; востребованность; название.

---

## 45. Производительность

Сайт должен быстро загружаться. Нельзя загружать огромные изображения без оптимизации.

Нужно:

- оптимизировать изображения;
- минимизировать лишние запросы;
- корректно загружать данные;
- использовать loading states;
- не загружать весь каталог сразу, если это не требуется.

---

## 46. Обработка ошибок

Если база данных недоступна, не должна появляться пустая страница. Показывается: «Не удалось загрузить данные. Попробуйте ещё раз.» и кнопка «Повторить».

---

## 47. Empty states

Если пользователь ещё не добавил ничего в избранное: «Ты пока ничего не сохранил.» и кнопка «Исследовать профессии».

Если поиск ничего не нашёл: «По вашему запросу ничего не найдено.»

---

## 48. 404

Если пользователь открыл несуществующую страницу:

**404** — «Похоже, этот путь пока не существует.» Кнопка: «Вернуться на главную».

---

## 49. Footer

Footer должен содержать: логотип; краткое описание; навигацию; основные разделы; переключатель языка; информацию о проекте; контакты/социальные ссылки, если используются.

---

## 50. «О проекте»

Отдельная страница. Нужно объяснить: проблему; идею Next Path; как работает платформа; для кого она создана; какие задачи решает.

Можно показать концепцию: Познай себя → Исследуй → Выбери → Построй путь.

---

## 51. Главный уникальный элемент проекта

Главная ценность Next Path — не сам тест. Подобных тестов много.

Уникальность заключается в связке всех этапов: тест → направление → профессия → университет → поступление → карьерный путь.

То есть пользователь не получает просто результат «Вам подходит дизайн». Он получает: «Вам подходит дизайн → вот подходящие профессии → вот необходимые навыки → вот университеты → вот программы → вот пример карьерного пути → вот что нужно сделать для поступления».

---

## 52. Сценарий пользователя от начала до конца

Пользователь открывает Next Path. Видит: «Не знаешь, кем стать? Начни с себя.» Нажимает «Пройти тест». Проходит тест.

Получает:

- IT / AI — 87%
- Инженерия / Архитектура — 78%
- Дизайн — 70%

Нажимает «Изучить IT / AI». Видит профессии: Software Developer; Data Analyst; AI Specialist; Cybersecurity Specialist и т.д.

Открывает Data Analyst. Видит: чем занимается; зарплату; востребованность; плюсы; минусы; навыки; предметы; карьерный рост.

Нажимает «Посмотреть университеты». Получает список университетов. Выбирает университет. Видит: программу; стоимость; требования; сроки; контакты. Добавляет университет в избранное.

Затем открывает «План поступления» и видит последовательность действий. После этого открывает «Карьерный путь» и видит, как может развиваться выбранная профессия.

Каждая кнопка должна либо выполнять действие, либо вести на существующую страницу.

Next Path должен восприниматься как реальный современный образовательный продукт, который можно показать школьнику, родителю, учителю, университету или на конкурсе.

Он не должен выглядеть:

- как школьный проект;
- как обычный шаблон;
- как сайт, полностью собранный нейросетью;
- как перегруженный портал.

Визуально он должен находиться между: образовательной платформой + карьерным сервисом + современным молодёжным digital-продуктом.

6. Открыть профессию.

---

## 58. Финальная концепция

Next Path — это не просто профориентационный тест. Это цифровой навигатор для школьника.

Он отвечает на пять последовательных вопросов:

- «Кто я?» → тестирование.
- «Что мне подходит?» → направления.
- «Кем я могу стать?» → профессии.
- «Где этому учиться?» → университеты.
- «Что мне делать дальше?» → план поступления + карьерная карта.

Именно эта логика должна оставаться основой всего продукта.

---

## 59. Главный принцип разработки

При разработке каждой страницы необходимо задавать вопрос: «Помогает ли эта функция школьнику сделать следующий шаг в выборе профессии?»

Если да — она должна быть понятной, функциональной и легко доступной. Если это просто декоративный элемент — он не должен усложнять интерфейс.

Главная цель Next Path: не перегрузить школьника информацией, а провести его от неопределённости к конкретному следующему шагу.
